# User Story Examples Across the Four Product Domains

## Standard format

As a **[user or actor]**, I want **[capability or action]**, so that **[outcome or value]**.

Stories describe user needs and outcomes. They should be refined with context, constraints, dependencies and testable acceptance criteria.

## 1. Corporate Travel Management

- As a traveller, I want to create a trip request with multiple destinations, so that I can plan a complete business journey in one place.
- As an approver, I want to see policy outcomes and estimated cost for each trip segment, so that I can make an informed decision.
- As a traveller, I want to access my itinerary and booking status on mobile, so that I can manage my trip while away from my desk.
- As a travel manager, I want to compare actual, committed and forecast spend, so that I can monitor the travel programme.

## 2. B2B & B2C Travel Technology

- As a travel agent, I want to search and compare flights, hotels, activities and transfers, so that I can create suitable travel options for customers.
- As a direct customer, I want to see transparent prices and cancellation terms, so that I can make an informed booking decision.
- As a platform operator, I want to monitor supplier booking responses, so that I can identify integration failures and unresolved reservations.
- As a customer, I want to book a dynamic package, so that I can arrange compatible travel components in one journey.

## 3. Healthcare System — HIMS / EHR / Laboratory

- As a clinician, I want to review a patient's relevant clinical record, so that I can make informed decisions within my authorised workflow.
- As a laboratory technician, I want analyser results to be associated with the correct specimen and order, so that results can be reviewed accurately.
- As a laboratory supervisor, I want flagged or unmatched results routed for review, so that unvalidated information is not silently released.
- As a hospital administrator, I want to monitor workflow and interface exceptions, so that operational issues can be addressed.

## 4. Vulnerability & Incident Management

- As a security analyst, I want scanner findings enriched with asset context, so that I can prioritise meaningful vulnerabilities.
- As an incident responder, I want related alerts correlated with an incident, so that duplicate operational work is reduced.
- As an asset owner, I want remediation tasks and SLA status to be visible, so that I can track outstanding risk.
- As a security manager, I want dashboards showing incident trends and remediation performance, so that I can assess operational effectiveness.

## Story quality checklist

- User or actor is clearly identified.
- Need is based on evidence or an explicit assumption to validate.
- Desired outcome or value is understandable.
- Story is small enough to discuss, estimate and deliver.
- Dependencies and constraints are visible.
- Acceptance criteria are testable.
- Edge cases, permissions, accessibility and auditability are considered.
- Analytics or measurement needs are captured where relevant.
- Clinical, security, financial or operational controls are considered where relevant.

## INVEST heuristic

- **Independent:** minimise unnecessary dependencies.
- **Negotiable:** describe the need, leaving room for solution discussion.
- **Valuable:** provide a clear user or business outcome.
- **Estimable:** include enough context for the team to assess the work.
- **Small:** keep scope manageable.
- **Testable:** define observable acceptance conditions.

> The examples are portfolio illustrations. Validate the underlying workflows and business rules with the relevant users and stakeholders before treating them as delivery requirements.
